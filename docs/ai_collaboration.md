# AI辅助开发与复核记录

下列记录来自实际开发中的检查与修正；开发工具自检与用户人工签核分开。

| 环节 | 检查发现与处理 |
|---|---|
| 数据范围 | 只使用既有通识标签。标题内标签括号曾导致漏匹配，剥除括号后仍要求与原GPA精确对应，未匹配记录保留。 |
| 工具与RAG | 采用Qwen原生工具调用、本地状态和已有知识库检索；云端片段须匹配本地评论，避免错误归属。 |
| 状态管理 | 真实多轮输出曾声称取消GPA但状态未变，增加明确取消处理及回归；其他类别取消仍有已知边界。 |
| 证据与数量 | 发现教师记录数被误称不同课程数，改为程序核对、呈现真实数量与引用。 |
| 比较 | 模型曾只分别取证，未调用比较；对有效对象补充真实比较调用并在日志标记来源。 |
| 普通交流 | 放宽问候、感谢和解释类请求，允许模型自然回答，同时保留原选课状态；混合查课请求仍需工具。 |
| 公开发布 | 完整数据、凭证和个人状态不公开；构造明确标注的样例，测试独立建库，重新验证公开版。 |

未进行旧新方案的公平效果对照，未报告未经测量的提升幅度。2026-11-02实际失败和当前边界见known_issues.md。


## 2026-11-03：教师评价追问

真实对话中，用户在选课结果后继续要求总结某位教师的评价。旧逻辑只认可本轮新查出的ID，且不接受工具执行后的自然语言回复，导致已有上下文被误拦截。现在从上一轮候选确认教师，按教师ID读取最多20条评论，并将实际课程与引用提供给模型；兼容正文附元信息，数量措辞记录警告，失效正文引用移除，缺少的评论引用元信息使用实际已取回的评论补齐。未知实体和结构化硬条件继续按目录处理。

公开版用虚构样例复现上下文追问、工具后自然语言、失效引用处理及更换教师时不误用旧对象；完整数据另进行了真实Qwen HTTP验证，评价追问与感谢回复各一次生成即完成。该次追问读取本地评论，没有再次请求云端知识库。另一次独立真实百炼检索的无原文摘要见`rag-retrieval-summary.json`。
